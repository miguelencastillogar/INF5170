## Configuración requerida en Supabase

La aplicación utiliza el proyecto configurado previamente en la Práctica 7. La tabla de registros guardados se muestra después del login y se actualiza al guardar un formulario. Antes de probar el inicio de sesión, crea desde el panel de Supabase un usuario de prueba con correo y contraseña. El portal no permite registro público de usuarios.

En el SQL Editor de Supabase, ejecuta el siguiente script para crear la tabla del formulario y restringir cada registro al usuario autenticado que lo creó:

```sql
-- Tabla para almacenar los envíos del formulario multipágina.
create table if not exists public.registros_finales (
    id bigint generated by default as identity primary key,
    user_id uuid not null references auth.users(id) on delete cascade,
    nombre varchar(120) not null,
    correo varchar(254) not null,
    telefono varchar(30),
    motivo varchar(30) not null
        check (motivo in ('consulta', 'comentario', 'otro')),
    detalles varchar(2000),
    creado_en timestamptz not null default now()
);

-- Habilitar seguridad a nivel de fila (RLS).
alter table public.registros_finales enable row level security;

-- Un usuario solo puede insertar filas asociadas a su propio UUID.
create policy "Usuarios autenticados insertan sus propios registros"
on public.registros_finales
for insert
to authenticated
with check (auth.uid() = user_id);

-- Un usuario solo puede consultar sus propios registros.
create policy "Usuarios consultan sus propios registros"
on public.registros_finales
for select
to authenticated
using (auth.uid() = user_id);

grant select, insert on public.registros_finales to authenticated;
grant usage, select on sequence public.registros_finales_id_seq to authenticated;
```

> Si las políticas ya existen, PostgreSQL avisará al intentar crearlas de nuevo. En ese caso, revisa las políticas existentes antes de volver a ejecutar las instrucciones de creación.

## Pruebas manuales obligatorias

1. Abrir la URL publicada y verificar que aparece el login.
2. Intentar acceder con credenciales incorrectas; la aplicación debe rechazar el acceso.
3. Iniciar sesión con el usuario de prueba creado en Supabase.
4. Confirmar que el menú se carga desde `data/menu.json` y que sus enlaces llevan a las prácticas correctas.
5. Completar cada paso del formulario; comprobar que no se avance si faltan campos obligatorios.
6. Guardar el formulario y verificar que se muestra un identificador de registro.
7. Confirmar en Supabase que la fila existe en `registros_finales`.
8. Cerrar sesión y comprobar que se vuelve a la pantalla de acceso.
9. Repetir la prueba en una ventana privada o en otro navegador.

## Seguridad y limitaciones conocidas

- Solo se utiliza la clave pública publishable/anon en el navegador. Nunca incluir una clave `service_role`.
- La seguridad real de los registros depende de RLS; no debe confiarse solo en ocultar elementos de la interfaz.
- El usuario de prueba y su contraseña deben compartirse con el docente por el canal de entrega, no guardarse en el repositorio.
- Los enlaces del menú deben contrastarse con el árbol definitivo de prácticas; algunos directorios del portafolio pueden no tener una página HTML de entrada.
- Esta entrega es candidata: autenticación y persistencia dependen de la configuración real de Supabase y requieren validación en navegador.
